## 2026-10-12: end-to-end failures on #328, fixed in code

The ready-for-review run failed three end-to-end checks on every retry. All three were regressions from this phase, not intended changes, so the code changed and the end-to-end expectations did not. No new rule: both fixes are corrections to rules 1115 and 1120.

| Failing check | Cause | Fix |
|---|---|---|
| `e2e/app-routes.spec.ts` "/{lang}/app/start renders for a signed-in owner" (owner with a brand goes to `/app`) | Rule 1115 added `src/app/[lang]/app/loading.tsx`. A `loading.tsx` at the app root is a Suspense boundary around every page under `/app`, and a `redirect()` thrown behind a boundary is streamed as a client-side meta refresh with a 200 (Next's `redirect` docs, "streaming context"), not a 307. The start page's "already has a brand" redirect stopped happening on the server | The root `loading.tsx` is gone; the eight per-screen ones stay. The home page loses its route skeleton: a `<Suspense>` inside the page after its redirects would keep it, but the page tests (`tests/teams-ui.test.ts`, `tests/handoffs.test.ts`, `tests/handoff-auto.test.ts`, `tests/cross-review.test.ts`) render it with `renderToStaticMarkup`, which stops at the fallback, so that is left to phase 2b. Pinned in `tests/uiux-phase2.test.ts` (rule 1115, "no loading.tsx at the app root") |
| `e2e/redirects.spec.ts` "/{lang}/app/verify sends a signed-out visitor to the login page" | The same boundary: `/verify` is in the layout's public list, so the redirect to login is the verify page's own, and it was streamed | The same fix. Login, signup (signed in, to `/app`), `/app/admin` (to `/admin`) and the home page's "no brand yet" (to `/app/start`) were hit the same way and are server redirects again |
| `e2e/auth-flows.spec.ts` "a new account with a carried site lands on the review step" (`getByRole("heading", { level: 2 })` matched 7) | Rule 1120 gave each rail group an `<h2>` inside a named `<section>`: six headings before the screen's own h1 and h2s in a screen reader's heading list, on the same level as the screen's sections, and six region landmarks inside the one nav | The group titles are plain labels on `role="group"` + `aria-labelledby` (announced as "Work, group" on entry). The heading list is the page's alone, so the test stays as it is and also guards that. Pinned in `tests/uiux-phase2.test.ts` (rules 1120-1121) |

Not changed, for phase 2b: the `loading.tsx` of chat and reports still sit above those pages' "no brand yet" redirects to `/app/start`, so for an account without a brand file those two redirects are a meta refresh (they still work, with and without JavaScript). The fix for those and for the home page's skeleton is the same: redirect first, then wrap the body in `<Suspense fallback={<RouteLoading />}>`, with the page tests moved to a renderer that waits for Suspense (`renderToReadableStream` / `prerender`).
