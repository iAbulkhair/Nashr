## Decisions (delegated by the founder, made on 2026-10-20)

1. On-demand where there is a tool loop only. The chat (the one caller with a tool loop) gets the stub and reads a file with the existing free `read_file` tool, so no new tool and no change to the tool list's cost (the chat prefix pinned by `tests/pricing-floor.test.ts` is unchanged). One-shot callers keep the text inline: they cannot fetch.
2. The out-of-date table above. Sources that change outside Thakeen are flagged sooner; what Thakeen recomputes is never flagged.
3. Expand only. `WFile.src` is optional and the fallback reading is permanent, so there is no contract step and no conversion script; a release that rolls back writes files without `src`, which the new code reads by the fallback.
4. A crawl's address is a label: stored only when clean, never fetched by this change. Refreshing stays with the importers, which already fetch through `safeFetch`.
5. Credits: reading a reference is free and runs only inside the owner's chat turn, after the input gate; checked in code (not in `TOOL_ACTION`, no write, no charge), not only in the prompt.
6. MCP `read_file` (`src/app/api/mcp/route.ts`) is unchanged: it answers the owner's own client, not an agent.
