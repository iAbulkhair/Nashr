# Coverage: profile fields sent by GET /api/profile (rule 787)

Status on 2026-10-09 on branch `claude/beautiful-albattani-ac2a11` (PR #302): rule 787 added. Its row moved here from `docs/system/tests.md` when the branch merged main (rule 788).

| # | Rule | Verified today | First test to write |
|---|---|---|---|
| 787 | `GET /api/profile` builds the `user` it sends from fields it names, never by spreading the stored record and removing a list: `SUMMARY` (`plan`, `credits`, `trialEnds`, `createdAt`, `renewedAt`) for every seat, and for the owner (and a founder acting as the owner) `OWNER`, which adds `name`, `email`, `lang` and `phone`; then the deal's terms (`{credits, priceSar}`, rule 243), the packs' balances (`topupBalance`, rule 453) and `role`. A member's `user` is its own `name`, `email`, `lang` and `role` with `SUMMARY` and the packs. Nothing else of the record is sent: not `passHash`, the revocation stamps, `agentSpend`, `seats`, `billing` (the Paymob intent reference, transaction ids, the card), `grants` (rule 783), `referredBy`, the first-month offer, held charges, chat settings or a field added to `User` later, and a field this build has never heard of (written by a later release, or by hand) is not sent either, so a rollback to this build or later cannot leak a new private field. | test (`profile-allowlist.test.ts`: an owner record with every persisted `User` field set, typed `Required` so a new field fails the type-check until the fixture sets it, comes back with exactly the owner keys and none of the stored secrets; a founder acting as the owner gets the same keys and a member exactly its own; a field unknown to the route, written straight to `user:{email}`, is not sent) | done |
