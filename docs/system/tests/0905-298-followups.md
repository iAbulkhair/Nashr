## Notes

- Rule 905 changes the account wipe from "deletes the conversation keys" to "deletes them under the writer lock": the key list in `account.ts` still names `conv:`, `chat:` and `convlock:` for an id `deleteConversation` refuses (a malformed one) and for a lock a dead writer left (10 s TTL).
- The route answers 500 when a conversation cannot be locked (`DELETE /api/account` and the console's `delete` do not catch the throw, as they do not for a failed link revocation); the profile page shows its generic failure and the owner presses again.

- Dropped, no rule: the `LARGE_REPLY` variant for a conversation on a picked model ("switch this conversation to Automatic"). Its premise was that Opus 5 gets about 80% of Automatic's per-turn room, so a picked model ends a turn in `LARGE_REPLY` where Automatic would still answer. The final form of #298 prices the pickable Opus as Opus 5.5, whose rates are exactly twice Sonnet 5.5's against a ceiling twice as large, so every pickable chat model has the same cliff as Automatic (141,396 characters of prefix, pinned in `tests/pricing-floor.test.ts`, "the cliff"). Switching to Automatic would not help, and the text would say something false. If a pickable chat model with less room is ever added, that test fails first; the wording then needs its variant.
- Rule 907 narrows the known gap of row 833 to the surfaces that keep the default's hold: the profile panel's "extra messages on credits" row (`≤ hold`), `POST /api/billing/chat-overflow`, `GET /api/profile` and the founder console. Which wording they should carry for an account whose conversations run on a Premium model is a copy decision, left for the founder; nothing about them is a price, unit or hold.

## Not pinned

- A conversation created by a request that started before the wipe and writes its record after the wipe read the index (`createConversation` is not under the lock) can leave a record and an index entry. The request must have passed `currentUser()` before the account record was deleted; not scheduled.
