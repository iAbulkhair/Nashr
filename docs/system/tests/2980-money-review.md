# Coverage: money review fixes (rules 2980-2984)

Status on 2026-10-22 on branch `claude/thakeen-nashr-review-tests-292d14`. A reviewer reported six money defects in billing, founding places and the chat allowance. Each was checked against the code first; five are real and fixed here with a test, one (the chat overflow gap) is real but left for the founder because its fix changes rule 310. Release step: expand for rule 2982 (the founding sets' members move from the address to the account id; freeing removes both, so rows of either shape leave; while ids equal addresses (R1) both are the same member, and the contract step, freeing by id alone, waits until no address member is left). None for the others: they change no stored shape (rule 2984 only keeps an existing `billing.pending` field longer).

Known and left for the founder (not changed here):

- Chat "continue on credits" with parallel turns (review finding 4). `reserveChatTurn` lets an overflow turn through when the session's copy of the balance covers `chatHoldFor(model)` and reserves nothing; `settleChatOverflow` bills `min(owed, balance now)`. N turns started together on a balance of one hold all pass, and after the first settles the rest bill 0, so up to (N - 1) holds (2 credits each on Sonnet 5.5, 4 on Opus) of model cost go unbilled per burst. The suggested fix (take the hold before the turn and settle against it) contradicts rule 310 ("nothing is held or taken before the turn", so the turn's own tools can spend the whole balance) and needs a founder decision. A smaller option that keeps rule 310: count overflow turns in flight per account (an expiring counter) and require a balance of `hold x in-flight turns` at the gate.
- `POST /api/admin/founding` freed an ended seat or lock with the login address; it now passes the account (`{ id, email }`) like the other two call sites (rule 2982, `tests/founding.test.ts` admin grant cases).
