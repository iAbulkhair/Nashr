# Coverage: money fixes before payments go on, and two price-copy fixes (rules 1300-1308)

Status on 2026-10-12 on branch `claude/money-price-fixes-7604ef`: three money bugs from the 2026-10-11 360 study (G-005, G-012/G-013, G-016 = issue #79) and two price-copy fixes, decided by the founder on 2026-10-12, before Paymob KSA card payments are switched on. Every rule is written and pinned in `tests/money-price-fixes.test.ts`, `tests/paymob.test.ts` (section "a refund ends the plan") or `tests/generate-batch.test.ts`. Rule 1309 is held for this batch and unused.

`User.handPlan` is a new optional stored field: this release is the **expand** step of rule 679 (new code reads a record with or without it; old code ignores it and keeps it through its saves). No data conversion: a plan set by hand before this release has no paid-through day and refills as before until the founder sets one. The contract step (a hand-set paid plan without a day stops refilling) is a later release and the founder's call.

## Not pinned

- A batch that returns fewer items than asked (3 of 10) is still charged in full: rule 1306 only covers zero items. Open question from issue #79.
- The media engine's refund on a failed image or video was not traced for the empty case in this batch.
- The founder console has no refund button for a Paymob payment: the refund is API only (`POST /api/admin/payments/{email}` `refund`).
- The saved card token (`paymob:card:{email}`) stays after a refund ends the plan, as after a plan set by hand: a later checkout can turn automatic renewal on again. Open question.
- After a hand-set plan's paid-through day the account keeps the plan's name, seats and chat allowance and is not locked; only the monthly credit refill stops. Open question.
- A plan set by hand mid-month with a day in the next month still gets that next month's refill on the 1st if the day has not passed (the refill runs by calendar month, the day is compared on the day of the refill).
