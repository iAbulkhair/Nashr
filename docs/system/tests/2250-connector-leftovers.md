# Coverage: fixed-host provider replies capped, sitemaps held to the site, and the connector tests #393 left open (rules 2250-2251)

Status on 2026-10-19 on branch `claude/connector-hardening-leftovers`, cut from `claude/api-platform-integrations-ce2972` (PR #393, rules 2160-2249) while that pull request is open. Rule 2250 carries rule 2245's cap to the providers at fixed hosts: Shopify, Salla, Zid, Meta, Meta Ads, X, every OAuth token exchange and refresh (`oauth.ts`), and Telegram, Brevo and Klaviyo in `keyed.ts`. Their answers were read with an uncapped `res.json()` or `res.text()`; they now go through `responseJson` or `responseText` with `PROVIDER_REPLY_BYTES`, the same 8 MB as `STORE_REPLY_BYTES` (flows section 12 step 3c). A refusal whose body is too large to read keeps its status in the error (an OAuth `{provider} token {status}`, an X `x {status}: `), so a revoked token is still told from a passing failure. Rule 2251 holds every sitemap the no-key catalog import fetches to the site's own host or its www twin: a `Sitemap:` line of robots.txt and a child `.xml` of a sitemap index on another host are skipped, not fetched. Before, only product links were held to the host (rule 2248), so a site could make the import spend its 40 s and up to a dozen fetches on any public host it named (flows section 11 step 10d). The sitemaps protocol keeps an index's sitemaps on the index's host; the cost is that a site cross-submitting its sitemap from another host through robots.txt falls back to its homepage links. The change also adds the two behavioural tests #393 listed as next for rules 2242 and 2247.
