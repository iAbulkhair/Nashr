# Coverage: Zid's tokens are refreshed 60 days before they lapse (rules 2210-2213)

Status on 2026-10-18 on branch `claude/zid-refresh-lead` (cut from `claude/api-platform-integrations-ce2972` e25f2ca5, with rule 2192 from `claude/distracted-tharp-551077` 441495cc cherry-picked so the refresh lock and the keep-alive are both present; local, not pushed). Rules 2180-2199 are reserved by the Salla Easy Mode spec and 2200-2209 are taken by the integration branch; checked against local branches and the one open pull request (#387, rules 1980-1999).

Before: `getFreshConnection` (`src/lib/connectors/fresh.ts`) refreshed a token five minutes before its stored expiry, for every provider. Zid's docs (Authorization, read 2026-10-18) give the manager token and the refresh token one year each and advise refreshing about ten months in, so a refresh in the last minutes could find the refresh token gone with the access token, and the owner would have to connect the store again. The stores cron's keep-alive (rule 2179) picked only expired tokens of providers with `oauth.refreshTokenDays` (Salla). The refresh body did not carry `redirect_uri`, which Zid's docs list for the refresh request.
