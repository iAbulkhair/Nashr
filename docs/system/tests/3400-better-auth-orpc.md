# Coverage: better-auth and oRPC behind AUTH_ENGINE (rules 3400-3434)

Status on 2026-10-23 on branch `claude/sup-foundation-migration`. Spec: `docs/superpowers/specs/2026-10-23-better-auth-orpc-migration.md`. Release step: **expand**. With `AUTH_ENGINE` unset nothing changes: no new route answers, no new cookie, key or field is written. Every test below runs with the switch off and on where the rule has two sides.

| # | Rule | Verified today | First test to write |
|---|---|---|---|
| 3400 | `AUTH_ENGINE=better-auth` turns the better-auth engine on; it is read at call time (`authEngine()` in src/lib/auth-engine.ts), so one build serves both engines and a rollback is one variable. Any other value, or none, is the legacy engine | `tests/better-auth-adapter.test.ts` (rule 3400) | none |
| 3401 | The engine also needs `BETTER_AUTH_SECRET` of 32 characters or more; a missing or short secret keeps the legacy engine (fails closed) and nothing logs the value | `tests/better-auth-adapter.test.ts` (rule 3401) | none |
| 3402 | better-auth 1.7.10, @orpc/server, @orpc/client and @orpc/tanstack-query 1.15.7 and @tanstack/react-query 5.104.3 are pinned exactly in package.json and package-lock.json, and the lockfile keeps the `@rolldown/binding-linux-*` entries (CLAUDE.md lockfile rule) | `tests/better-auth-adapter.test.ts` (rule 3402) | none |
| 3403 | The adapter's `user` is the login, projected and never written: by `email` through `getLogin` (the projected address must equal the asked one), by `id` through the person record and `getLogin` with the same pid. `emailVerified` is true, the password hash never appears; a query by any other field answers nobody | `tests/better-auth-adapter.test.ts` (rule 3403: owner, member, unknown, other spelling) | none |
| 3404 | The adapter's `account` rows are `credential` (the person's bcrypt hash, `accountId` = pid) when a hash exists, and `google` only when `googlesub:{login}` and `google:{sub}` name each other; a query without `userId` answers nothing | `tests/better-auth-adapter.test.ts` (rule 3404) | none |

| 3407 | The adapter writes a `session` only for a 64-hex token the session gate approved in this process within 30 s (src/lib/better-auth/approvals.ts), and writes it with `issueSession`, the body `createSession` runs: the same record keys, cookie and device entry. An approval is used once | `tests/better-auth-adapter.test.ts` (rule 3407) | none |
