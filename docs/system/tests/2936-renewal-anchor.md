# Coverage: the allowance renews on the plan's own day (rule 2936)

Status on 2026-10-22 on branch `claude/thakeen-nashr-bugs-tests-tracking-9eac9c`. Money review F2. The founder decided on 2026-10-22: "renew each plan's allowance on its own paid-period date, not on the 1st of the month." Before this change, a plan set on the 20th got its allowance that day and again on the 1st, eleven days later.

Release step: **expand** (rule 679). `User.renewedOn` (the Riyadh day of the last renewal) and `User.renewAnchor` (the day of the month a hand-set plan renews on, 1-31) are new and optional. `renewedAt` (YYYY-MM) is still written beside them. Old code ignores the new fields and reads `renewedAt` as before. **Contract** (a later release): once every paid record has `renewedOn`, the `renewedAt` reading in `lastRenewal` may go. No data script is needed: every renewal and plan change writes the new fields.
