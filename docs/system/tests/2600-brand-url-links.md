# Coverage: the brand in every app link (rules 2600-2603)

Status on 2026-10-21 on branch `claude/brand-url-task8`: Task 8 of `docs/superpowers/plans/2026-10-20-brand-url.md`, after #418 (multi-workspace M2) and #419 (brand id in the URL) are both on `main`. #418's merge commit `b42f526b` had already composed the two (one builder `appHref(lang, path, handle, brand)`, `pageHref`, `appHrefFor`/`appHrefIn` with a brand argument, one fetch wrapper `installBrandFetch({ workspace })`, one proxy rewrite of `/w/{handle}` ahead of the `[...legacy]` page, legacy 307s keeping the handle; `tests/multi-org-brand-url.test.ts`, `tests/multi-org-brand-url-off.test.ts`). This change does the rest: the links that still went to an old path and took the `[...legacy]` hop to the session's stored brand, which for a multi-brand account can be another brand than the one the link is about. Release step: expand (no stored shape changes; old links still answer 307).
