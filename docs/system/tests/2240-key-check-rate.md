# Coverage: failed key checks limited per workspace, and a deadline on every connect call (rules 2240-2243)

Status on 2026-10-19 on branch `claude/api-platform-integrations-ce2972`. `POST /api/connect/{provider}/key` checks the credentials it is given against an outside service (a WordPress site's username and application password, a WooCommerce, Odoo or PrestaShop key, a Telegram bot token, a Brevo or Klaviyo API key) and had no rate limit, so a signed-in account could use Thakeen's servers to try passwords against any WordPress site. Failed checks now cost a hit in two buckets of the caller's own workspace (flows section 12 step 2a); a passing check hands its hits back. Rule 2241 gives the Klaviyo key check (the one direct `fetch` of the route) the 30 s `providerTimeout()` deadline every other provider call has (rules 1343-1344), and widens the rule 1344 source scan from eight named connector files to every file under `src/lib/connectors` and `src/app/api/connect`, so a new call without a deadline fails the check. Rule 2242 limits connect starts to twenty an hour per workspace, because each Composio start opens a pending connection on the one Composio account every tenant shares (flows section 11 step 1a). Rule 2243 limits the manual sales sync (open to any member) and the product import to six an hour each per workspace, because each reads pages from the store (flows section 11 step 11a). Rules 2244-2249 are reserved for this branch.
