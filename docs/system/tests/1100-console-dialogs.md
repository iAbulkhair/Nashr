# Coverage: founder console changes in one in-page form (rules 1100-1102)

Status on 2026-10-11 on branch `claude/console-dialogs`: the founder console's Users section (`src/components/admin/Users.tsx`) asked its changes through 26 `window.prompt` and `window.confirm` calls, up to six in a row for one change (P0 E-001 of the 360 study: before rule 960, Cancel on the reason prompt still applied money changes). A browser or frame can block those dialogs (an artifact frame, "prevent more dialogs"), and they speak the browser's language. Every change now asks in one form in `ActionDialog` (`src/components/admin/ActionDialog.tsx`, a native `<dialog>` opened with `showModal()`, the pattern of `TempPasswordDialog` and `DeleteAccountDialog`), and its values are checked by the parsers in `src/lib/admin-input.ts`. Rule 960's checks were rewritten for the form. Rules 1011-1099 are taken by local branches (`claude/monitoring-ci-parity`, `claude/prompt-studio-specs`, `claude/uiux-phase1`), so this change starts at 1100. `npx next build` was not run locally (Turbopack cannot bind its port in the sandbox); CI builds it
