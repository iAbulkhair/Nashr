## Rulings

Decided by the founder's delegation on 2026-10-13 (R-M1 on 2026-10-21); the text of each is in `docs/superpowers/plans/2026-10-20-brand-url.md`, section "Rulings".

- R-B1: Part B (brand limits per plan, rules 1390-1395) needs no new code; re-checked 2026-10-21, one dated line in `docs/system/tests/1390-brand-limits.md`.
- R-C1: the header is `x-thakeen-brand`, not the spec's `x-nashr-brand`, matching M2's `x-thakeen-ws`.
- R-C2: the guard lives in the proxy (`src/lib/brand-guard.ts`), not in the route wrapper; a coverage test holds its lists to the routes on disk.
- R-C3: a bad selector (unknown, archived, another account's, malformed) is Next's 404 from `currentUser()`; the status is the contract, no `brand_not_found` body.
- R-C4: release step is expand: the guard ships in `"log"` mode and the contract release flips it to `"enforce"` (409).
- R-C5: `/{lang}/app` goes to the last chosen brand whatever the brand count; the all-brands overview page is deferred.
- R-C6: settings splits by the spec's rule; `brand`, `connections` and `governance` move under `b/{id}/settings/`.
- R-C7: a session written before R1 that sends a selector reads the brand list in one more round; requests without a selector are as before.
- R-C8: a link from an account page to a brand section uses the session's brand (`u.brandId`) from the layout; a client component never guesses a brand.
- R-C9: rules 885-896 from the spec's block, 897-899 spare, none from 2500-2549.
- R-C10: `settings/notifications` reads and writes the brand's profile, so it moves under `b/` too.
- R-C11: the guard's list covers the five routes scoped only through `handler({ auth: "user" })`.
- R-C12: mixed `PUT /api/profile` is in `BRAND_API`; shell components on account pages that mutate a brand route send the session's brand explicitly.
- R-C13: navigations to brand GET routes carry `brand={id}` (`apiHref`); the proxy copies it into the header on GET/HEAD `/api/` only, never for a mutation.
- R-M1: #418 (multi-workspace M2) lands first; this branch follows its builder shape under non-colliding file names and merges after #418 with Task 8 done; the composed address is `/{lang}/app/w/{handle}/b/{brandId}/…`.

## Release step

Expand (this release): the proxy sets the header from the path, `BRAND_GUARD_MODE` is `"log"`, a request without a header falls back to the session's brand, old page paths answer 307. Contract, in a later release after one release of logs shows no `brand_missing` from current pages: `BRAND_GUARD_MODE` becomes `"enforce"`. Later again, the `[...legacy]` page goes once mails and bell entries stop naming old paths. The release pull request names the step. No data conversion is needed (no stored shape changes).
