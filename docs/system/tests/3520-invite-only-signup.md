# Coverage: invite-only sign-up switch (rules 3520-3526)

Status on 2026-10-23, branch `claude/sup-invite-only-signup`, not pushed. A server-side switch, `SIGNUP_MODE` (docs/system/variables.md section 2), default open, so a deploy without it behaves as today. With `invite`, every path that creates a new login needs a standing team invite; existing people still sign in and accepting an invite still works. Code in `src/lib/signup-mode.ts`, the two invite checks in `src/lib/team.ts` (`inviteTokenFor`, `verifiedAddressInvited`), the gate in `src/app/api/auth/signup/route.ts` and `resolveGoogle` (`src/lib/google-signin.ts`), the closed page in `src/components/app/SignupClosed.tsx`. Flow: docs/system/flows.md section 1 step 10. Release step: none, no stored shape changes (only reads of `invite:{id}`, `invites:{aid}` and `invitesfor:{email}`). Rules 3527-3529 are reserved for this change and unused.

| 3520 | The switch is the environment variable `SIGNUP_MODE`, read on the server at call time and never public. Only `invite` (trimmed, any case) closes sign-up; unset, empty, `open` and any other value keep it open | `tests/invite-only-signup.test.ts` ("rule 3520") | none |
