# Coverage: Geidea KSA card payments (rules 3900-3917)

Status on 2026-10-24 on branch `claude/sup-geidea` (local, not pushed). Geidea replaces Paymob as the card provider (spec `docs/superpowers/specs/2026-10-18-geidea-payment-provider-design.md`; the spec's own numbers 2700-2729 are not used, they were taken). Code: `src/lib/geidea.ts`, `src/lib/billing.ts`, `src/lib/payments/index.ts`, `src/app/api/billing/geidea/webhook/route.ts`; `flows.md` section 109, `permissions.md` row 151b and "Geidea billing", `variables.md` section 4b. Rules 3918-3949 stay free for the Geidea follow-ups.

Release step: expand (rule 679). New keys only (`pay:*`, section 3 of `architecture.md`), written only while Geidea is on; Paymob's `paymob:*` keys, payment ids and log lines are unchanged, and old code never reads a `pay:*` key. `Billing.provider`, `PayIntent.provider`, `PayIntent.agreementId` and `SavedCard.agreementId` are widened, read with a Paymob default. Off by default: no Geidea variable is set anywhere.

Everything Geidea's own test environment must still prove (signature strings, timestamp format, where the response codes sit, the MIT and refund calls, the order lookup) is marked UNVERIFIED in the spec and in `src/lib/geidea.ts`; these tests pin our side of each contract against a fake at `fetch`.
