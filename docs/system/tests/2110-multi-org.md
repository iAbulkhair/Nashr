# Coverage: multi-workspace membership (rules 2110-2139)

Status on 2026-10-19 on branch `claude/wave3-m1-expand` (spec `docs/specs/2026-10-18-multi-org.md`, plan `docs/superpowers/plans/2026-10-19-multi-org-m1.md`). This is wave 3a of the supastarter gap study of 2026-10-16. Release step: **M1 = expand** (rule 679): the new code reads the old and the new shapes, writes both for a home membership, and older builds ignore every new key and field, so a rollback to any earlier build is safe. `MULTI_ORG` is `false` through M1, so production behaves as today (rule 2132).

Every rule below starts as "not pinned yet" and changes status in the task that builds it. Task 1 (switch, branded ids, key builders, stored shapes) starts rules 2115, 2129, 2132 and 2137. Task 2 (read adapters: `src/lib/person.ts`, `src/lib/membership.ts`, `isPersonSuspended`) pins 2134 and 2136 and the adapter half of 2115, in `tests/multi-org-adapters.test.ts` (35 tests).

Not pinned until M2/M3/M4/S1 (reconciliation 17 of the plan): 2113, 2114, 2116, 2117, 2123 (M2: switch route, handles, `x-thakeen-ws`, create workspace, invites to existing persons, `p_` signups); 2127, 2128, 2130 (M3: person deletion, ownership transfer, the console people view); 2133 (S1: the conversion script); 2138 (M4: the contract release).
