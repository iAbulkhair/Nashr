## 1. Summary

Nashr is a single Next.js 16 app-router application (TypeScript, React server components, no separate backend) deployed on Vercel. It serves a bilingual (Arabic default, English) marketing site and an authenticated app under `/{lang}/app` in which a small-business owner, and since 2026-09-29 the admins and members the owner invites into the account, talk to eight AI agents (Noor marketing, Sami sales, Razan finance, Faris growth, Dana reporting, Majed executive, Layan product, Reem secretary; `src/lib/agents.ts`). Seven of them produce content "tasks"; Reem owns no task type and keeps the owner's own to-do list instead (`src/lib/secretary.ts`), for free. Agents call Anthropic models through `@anthropic-ai/sdk`, produce content "tasks" that land in an approval inbox, and can publish approved items to third-party platforms through connectors. All state lives in one Upstash Redis database reached through a thin adapter (`src/lib/db.ts`); when no Redis credentials are present the adapter silently falls back to a process-local in-memory `Map` (`memory`, `src/lib/db.ts:183`). There is no SQL database, no queue and no background worker: long work runs inside the request (route `maxDuration` up to 300 s), after the response via Next `after()` (`judgeLater`, `src/lib/judge.ts:192`, and the opportunistic media sweep `maybeSweep` in `src/lib/media/jobs.ts`), or in six Vercel cron jobs and one Upstash QStash schedule (Reem's tick, `/api/cron/secretary`, since 2026-09-30). Images and video come from fal.ai, kie.ai and Higgsfield and are copied to a Vercel Blob store (section 4(e)). Usage is metered in credits held on the owner's user record, shared by everyone in the account, and, since 2026-10-01, chat in messages: a monthly allowance per plan for the whole account, past which chat pauses unless the owner chose to continue on credits (`src/lib/chat-allowance.ts`, section 4(c)); who may do what inside an account is one role table (`src/lib/roles.ts`). The same agent capabilities are exposed to external AI clients through an MCP endpoint (`/api/mcp`) protected by personal bearer tokens or by a built-in minimal OAuth 2.1 authorization server; through it an owner's own Claude or ChatGPT subscription can also read the brand rules, check a draft and save it into the approval inbox without spending credits (`save_draft`, `src/lib/external-drafts.ts`; action `drafts`).

## 4. Request lifecycles

### (a) Marketing page
1. Browser requests `/`. `proxy.ts:34` redirects to `/{lang}` (and `/app` to `/{lang}/app`, rule 681). Other marketing paths pass through the proxy untouched (it matches every path since the staging lock; off staging it only acts on `/`, `/app` and app paths) and go straight to the route.
2. `src/app/[lang]/layout.tsx` and the page render on the server from static dictionaries. No session lookup, no Redis access.
3. Public forms call `/api/support`, `/api/affiliates`, `/api/tools/{tool}` from the browser. Only the tools route calls a model (anonymous limit 5 per IP per day, `api/tools/[tool]/route.ts:25-26`).

### (b) Authenticated app page
1. Request to `/{lang}/app/...` goes through the proxy, which sets `x-pathname` (`proxy.ts:42`).
2. `app/layout.tsx` calls `currentUser()`, which resolves the session to the ACCOUNT, the owner's `User`, with `actor`, `brandId` and `scope` set, or `null` (section 4(f)).
3. Anonymous and not a public path: redirect to `/{lang}/app/login` (`layout.tsx:28`). The redirect is skipped when `x-pathname` is empty.
4. Each page repeats its own guard (`currentUser()` then `redirect`) and reads data with `sc(u)` or, on several pages, `u.email` (see `permissions.md` section 2).
5. Client components then call JSON APIs with the same cookie.

### (c) Streaming chat turn with a tool call that generates content
1. `ChatPanel` posts `{text, conv, agent, stream:true}` to `POST /api/chat` with header `x-lang` (`src/components/app/ChatPanel.tsx:563`).
2. Route checks `currentUser()` (`api/chat/route.ts:28`), trims text to 4000 chars (`:31`, 400 `empty` when nothing is left), validates `agent` with `isAgentId`. Then, before anything is saved or a stream is opened: an ended trial (`trialOver`, since 2026-10-01, rule 330: 402 `trial_over` with `limit:"trial"` and a message linking the Subscription page, before any ceiling or allowance is touched), the per-account burst limit (`chatRefusal`: `chatCaps(u)`, 30 an hour and 150 a day on a paid plan, 10 an hour and 30 a day on a trial, `rate:chat:h:{email}` and `rate:chat:d:{email}`, the day counted only for a turn the hour allowed; 429 `slow_down` with `retry` and a message, rule 331), and since 2026-10-01 the plan's monthly chat allowance (`reserveChatTurn`, `:38`, `src/lib/chat-allowance.ts`): the message is counted on the account's counter with INCRBY; past the allowance it is taken back and the answer is 402 `{error: "chat_allowance", chat, credits}` (paused), unless the owner of a paid plan turned "continue on credits" on and the balance is at least `chatOverflowHold()` (5 credits, the most one message can cost), in which case the message goes ahead with nothing taken from the balance (the turn's own tools may spend it), or 402 `chat_credits` when the balance is below that. Only then it opens a `ReadableStream` SSE response with a 10 s `: ping` heartbeat (`:59`) and runs the turn through `runChatTurn` (`:61`), which settles it on every path.
3. `chat()` (`src/lib/chat.ts:363`): takes the turn's deadline first (`:365`, `deadlineFor(CHAT_MAX_DURATION_S)` = start + 285 s, since the route passes none), pushes the user message to `chat:{scope}[:{conv}]`, loads brand, this agent's preferences (`listPreferencesFor`), memory files, file names, connections, the thread (sent to the model through the history guard, `:401`, since 2026-10-01: `trimHistory` keeps the newest 16 messages that fit 24,000 characters, each cut to 6,000, a thread that starts with the first-run onboarding's assistant messages as it is, and `fitFirstCall` then drops the oldest until the first call has at least 4,000 output tokens) and the agent's recent feedback (`feedbackFor` with chat thumbs, in the uncached block) and, since 2026-09-30, the handoff notes other agents left for this one (`handoffNotesFor`, passed to `system` as the `handoffBlock` data block, uncached) in one `Promise.all` (`:391`), builds the system prompt (`system`, `:229`, called at `:395`; its uncached block starts with `nowLine`: the current date and time in the brand's zone), and, for each of at most `CHAT_MAX_CALLS` (5) calls, first works out its `max_tokens` (since 2026-10-01: the first call's from `fitFirstCall`, every later call's from `nextMaxTokens`, `:415`: what is left of the $0.14 per-message ceiling `CHAT_TURN_MAX_USD` after what the turn already cost and an upper estimate of this call's input, at most 8,000; below 2,048 no call is made and the turn ends with `CAPPED_REPLY`, or, when even the first call has no room, with `LARGE_REPLY`, which says the workspace is too large for one message and is not counted), then calls `client.messages.stream` with `CHAT_MODEL` (`claude-opus-5`) and the fifteen tools (`:425`; the nine content tools, Reem's five free to-do tools (four since 2026-09-29, `agenda_next` added on 2026-09-30) and, since 2026-09-30, the agents' handoff note `handoff_note` (a note that runs nothing, refused over MCP; Usage is metered per agent (`:432`), and each call's cost is added to the turn's total, which the route reads as `ChatTurn.usd` and never sends to the browser (`runChatTurn` strips it). A call the model ended at `max_tokens` (`:439`) is never acted on: its tool calls do not run, and its text is kept with `CUT_NOTE`.
4. The model returns a `tool_use` for `generate_content` or `draft_items`. `runTool` (`:581`, with the turn's deadline) first refuses, for `draft_items`, any type outside `DRAFT_TYPES` in code (`isDraftType`, `chat.ts:622`, since 2026-09-30, rule 250) before any read or charge, then hands the batch to `generateBatch` (with that deadline, which bounds the batch's cross-agent review) (`src/lib/generate-batch.ts`, `flows.md` 8.13, which also refuses a small ask of any other type): requires a brand, loads governance, rejects expired trials, `charge(user.email, cost, {scope, agent: agentForTask(type), cap: gov.agentCaps[agent]})` under `lock:user:{email}` (`credits.ts:72`), calls `generate()` (`noor.ts:174`: Opus generation, then Sonnet reviewer `critique`, optional dash stripping, then the cross-agent review when the type has reviewers and `gov.crossReview` is on). A `generate_image` call renders against the same deadline and starts nothing with less than 60 s of it left (`CHAT_RENDER_MIN_MS`, `:836`); its charge goes through `startMedia` with the item's owning agent and cap, like the image route.

6. `POST /api/media/hook/{provider}` is a hint: per-IP limit, 64 KB body cap, the kie signature when `KIE_WEBHOOK_HMAC_KEY` is set; only the provider task id is read, the job is found through `mjobref` under its stored scope, and `advance` runs in `after()` without `force`, sharing the poll throttle. 6. Founder console: `adminActor(req)` answers `"key"` for the admin key (header `x-admin-key`) or a live key session (cookie `nashr_admin` = a random id; `adminKeySession()` looks up `adminsession:{sha256(id)}`, checks the stored fingerprint against the current key and both limits (15 minutes idle, 12 h at most), and renews it at most once a minute), the founder's email when `isFounderActor(currentUser())` (actor kind `owner`, actor email equal to the account email, in `ADMIN_EMAILS`), else `null`; `isAdmin` and `isAdminCookie` follow it.
