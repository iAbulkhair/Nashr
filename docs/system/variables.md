# Nashr: environment variables (names only)

Every `process.env` reference in `src/`, `next.config.ts` and `scripts/` at HEAD `4959f7e`, updated on 2026-09-29 with the media providers (kie.ai, Higgsfield, Vercel Blob; section 3) and the routines cron (`CRON_SECRET`; it added no new name), and with the rows for `APP_ORIGIN`, `RESEND_API_KEY`, `MAIL_FROM`, `ADMIN_EMAILS` and `WAITLIST_ADMIN_KEY` updated on 2026-09-29 for teams, which added no variable. On 2026-09-30 phase 2 of Reem the secretary added `QSTASH_CURRENT_SIGNING_KEY` and `QSTASH_NEXT_SIGNING_KEY` (section 2) and two routes that read `CRON_SECRET`. Updated on 2026-09-30 for pricing phase 1: `PAY_LINK_BUSINESS` is new, and `PAY_LINK_AGENCY` is no longer read (section 4). Pricing phase 2 (2026-10-01: the chat allowance, the owner's "continue on credits" switch and the $0.35 per-message ceiling) added no environment variable: the allowance, the ceiling and `chatOverflowHold()` (5 credits: the least the balance must hold for a message on credits, and the most one is billed after the reply; nothing is held before it) are constants in `src/lib/pricing.ts`, and the new route `POST /api/billing/chat-overflow` reads none; the references below into files it changed (`src/app/api/mcp/route.ts`, `src/lib/auth.ts`, the billing page) were moved to the lines the code now has, and checked again after its review fixes of the same day, which added no variable either. No values are recorded here and no `.env*` file was opened to produce this list; names come from a source search for `process.env.` and from the `clientIdEnv` / `clientSecretEnv` fields in `src/lib/connectors/registry.ts`. Nothing uses the `NEXT_PUBLIC_` prefix, so no variable is compiled into client bundles; some are passed to client components as props by server components (noted below).

"Degrades gracefully" means the app keeps working with reduced function when the variable is unset. "Secret" means the value must not be disclosed.

## 6. Summary for auditors

- Total distinct names read: 50 (31 in sections 1 to 4; `VERCEL_ENV`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` and `TYPESAFE_API_KEY` added 2026-10-01; 19 in section 5, the 18 connector client credentials plus `META_CONFIG_ID`). Reem phase 2 (2026-09-30) added the two QStash signing keys; pricing phase 1 (2026-09-30) added `PAY_LINK_BUSINESS` and stopped reading `PAY_LINK_AGENCY`, which left the count unchanged, and section 4 keeps the retired name so the founder removes it. This summary said 44 before the QStash keys and 37 (19 + 18) before 2026-09-29, when it had not counted `META_CONFIG_ID`.
- Secrets (26): `KV_REST_API_TOKEN`, `UPSTASH_REDIS_REST_TOKEN`, `ANTHROPIC_API_KEY`, `TYPESAFE_API_KEY`, `WAITLIST_ADMIN_KEY`, `CRON_SECRET`, `QSTASH_CURRENT_SIGNING_KEY`, `QSTASH_NEXT_SIGNING_KEY`, `CONNECT_SECRET`, `TURNSTILE_SECRET_KEY`, `RESEND_API_KEY`, `FAL_KEY`, `KIE_API_KEY`, `KIE_WEBHOOK_HMAC_KEY`, `HIGGSFIELD_API_KEY_ID`, `HIGGSFIELD_API_KEY_SECRET`, `BLOB_READ_WRITE_TOKEN` (17 platform secrets), plus the 9 `*_SECRET` connector variables in section 5.
- Media variables are read in `src/lib/media/` and the webhook route only; the founder console (`GET /api/admin/media`) reports whether each is set, never a value.
- Fail closed when unset: `CRON_SECRET`, the QStash signing keys (the tick is refused; reminders fall back to the daily cron), key-based admin access (`WAITLIST_ADMIN_KEY`), email-based founder access (`ADMIN_EMAILS`, since 2026-10-01), OAuth connectors, and the media models of a provider whose key (or the Blob token) is missing.
- Fail open by design when unset: the Turnstile keys (no CAPTCHA on signup and forgot until both are set).
- Fail open or degrade unsafely when unset: Redis credentials outside a production deployment (in-memory store; a production deployment refuses every store call since 2026-10-01), `CONNECT_SECRET` (weak or shared encryption key), `APP_ORIGIN` (links and OAuth endpoints pinned to the hard-coded production origin).
- Values stored outside the environment but derived from it: `adminsession:*` records hold a SHA-256 fingerprint of `WAITLIST_ADMIN_KEY` (never the key); the `nashr_admin` cookie holds only a random id (2026-10-01; it held the raw key before).
- No startup validation of required variables exists; each is read at call time.
- Teams (2026-09-29) added no variable. The invite route reads `APP_ORIGIN` (through `ORIGIN()`) for the join link and `RESEND_API_KEY` and `MAIL_FROM` (through `mailReady()` and `sendEmail`) to email it; without mail the link is shown once to the inviter.
