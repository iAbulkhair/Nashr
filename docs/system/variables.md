# Nashr: environment variables (names only)

Every `process.env` reference in `src/`, `next.config.ts` and `scripts/` at HEAD `4959f7e`, updated on 2026-09-29 with the media providers (kie.ai, Higgsfield, Vercel Blob; section 3) and the routines cron (`CRON_SECRET`; it added no new name), and with the rows for `APP_ORIGIN`, `RESEND_API_KEY`, `MAIL_FROM`, `ADMIN_EMAILS` and `WAITLIST_ADMIN_KEY` updated on 2026-09-29 for teams, which added no variable. On 2026-09-30 phase 2 of Reem the secretary added `QSTASH_CURRENT_SIGNING_KEY` and `QSTASH_NEXT_SIGNING_KEY` (section 2) and two routes that read `CRON_SECRET`. Updated on 2026-09-30 for pricing phase 1: `PAY_LINK_BUSINESS` is new, and `PAY_LINK_AGENCY` is no longer read (section 4). Pricing phase 2 (2026-10-01: the chat allowance, the owner's "continue on credits" switch and the $0.35 per-message ceiling) added no environment variable: the allowance, the ceiling and `chatOverflowHold()` (5 credits: the least the balance must hold for a message on credits, and the most one is billed after the reply; nothing is held before it) are constants in `src/lib/pricing.ts`, and the new route `POST /api/billing/chat-overflow` reads none; the references below into files it changed (`src/app/api/mcp/route.ts`, `src/lib/auth.ts`, the billing page) were moved to the lines the code now has, and checked again after its review fixes of the same day, which added no variable either. No values are recorded here and no `.env*` file was opened to produce this list; names come from a source search for `process.env.` and from the `clientIdEnv` / `clientSecretEnv` fields in `src/lib/connectors/registry.ts`. Nothing uses the `NEXT_PUBLIC_` prefix, so no variable is compiled into client bundles; some are passed to client components as props by server components (noted below). Reem phase 3 B2a (2026-10-05) added no variable: the booking links' signing keys are derived from `CONNECT_SECRET` (section 2). Paymob KSA billing (2026-10-08, branch `claude/quizzical-galileo-5b3662`, draft, not merged) adds six names in section 4a; none is set anywhere yet, so online payment stays off and section 4's links stay the way to pay. Section 7 (2026-10-08) lists the four names the release scripts read on the machine that runs them; the app does not read them.

"Degrades gracefully" means the app keeps working with reduced function when the variable is unset. "Secret" means the value must not be disclosed.
