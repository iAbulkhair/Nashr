# Customer passkeys (wave 3c, release step "expand") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Each task is one sitting for one implementer; `npm run check` must be green at the end of every task.

**Goal:** A customer person (owner or member) can register up to ten passkeys in Security settings and sign in with one from the log-in page (button and browser autofill). The sign-in reuses `finishLogin`, so every gate of the password path applies. Passkeys are keyed by the M1 person id, follow address moves, die with the person, and sit behind a runtime off switch that defaults to on.

**Spec (binding):** `docs/specs/2026-10-20-passkeys.md` (threat table, decisions 1-13 and "Choices made inside the decisions", data shapes and keys, flows A-E, rules 2400-2429, release step, docs to update).

Start building only after #403 is merged to `main`: rebase or re-cut from `main` then, and re-check that rules 2400-2429 and flows section 99 are still free (`docs/system/tests/`, `docs/system/flows.md`, open PR titles). Tests list: `docs/system/tests/2400-passkeys.md` (rule 788: never append to `docs/system/tests.md`).

**Tech stack:** Next.js 16 (read `node_modules/next/dist/docs/` before writing a route or a page: `cookies()` and `headers()` are async), Upstash Redis through `src/lib/db.ts` (memory store under vitest), zod 4 (`z.looseObject`, `parseStored`), vitest, `@simplewebauthn/server` and `@simplewebauthn/browser`.

## Global Constraints

Every task respects all of these.

- **Isolation.** The pid of a passkey set comes only from our own records: `actingLogin(u).pid` on the manage routes, the reverse index forward-checked through `getPerson` and `getLogin` on sign-in (rules 2400, 2405), the pids a move already resolved. Never build a key from an address, an account id or any request value. `storedPersonId` is never called under `src/app`.
- **Keys** (all in `src/lib/keys.ts`, exact bytes): `personKey.passkeys(p) = passkeys:${p}`, `personKey.passkeyReg(p) = pkreg:${p}`, `globalKey.passkeyCred(hash) = pkcred:${hash}`, `globalKey.passkeyAuth(hash) = pkauth:${hash}`, `globalKey.passkeysOff() = "passkeys:off"`; rate buckets `pk:ip:${ip}`, `pkv:ip:${ip}`, `pkv:cred:${hash}`, `pkpw:${login}` as bucket builders beside the existing ones (keys.ts line ~164). `tests/key-registry-ratchet.test.ts`: the raw-key total (≤524) and `scopeParam` (≤90) do not rise.
- **Locks** (rule 2139): `inviteuse` → `lock:team:{aid}` → `lock:login:{email}` → `lock:person:{pid}` → `lock:member:{email}` → `lock:user:{aid}`. Passkey writes take only `lock:person:{pid}` (`withPersonLock`, not reentrant; a callee under a held lock takes `{ personLocked: true }`). `PERSON_LOCK_TIMEOUT` answers 409 `busy`. Both address moves hold both person locks (`withMovePersonLock`, 60 s expiry, the smaller pid first) and pass `{ personLocked: true }`; the wipe deletes are the only passkey writes without a person lock (rule 2414). (As built in Task 6: the earlier `userLockHeld` exception for the owner move is gone.)
- **Redis.** No `await db.*` inside a loop: deleting or rewriting N reverse entries is one `Promise.all` (or `pmap` from `src/lib/parallel.ts`).
- **Seam.** Only `src/lib/webauthn.ts` imports `@simplewebauthn/server` (rule 2427). Routes and `src/lib/passkeys.ts` call the seam. The seam passes a stored counter of 0 to the library; the counter decision is `counterOk` in `src/lib/passkeys.ts` (rule 2421).
- **Origin.** RP ID `new URL(appOrigin()).hostname`, expected origin `appOrigin()` (`src/lib/origin.ts`). Never `req.headers`, `Host`, `Origin` or `x-forwarded-*` (rule 2406). No new environment variable; `docs/system/variables.md` does not change.
- **Auth first.** Manage routes: `currentUser()` → `actingLogin(u)` → `forbid(u, "passkeys.manage")`. Public sign-in routes: the switch, then `allow` from `src/lib/rate.ts` before any other read. Console route: `adminActor` → `staffMay` → `secondFactorRefusal` → `reasonRefused` → `adminAudit`.
- **Secrets.** The nonce, the challenge, the credential id and the public key are never logged and never put in a URL. Logs name shapes and 8-hex hashes only.
- **Copy.** Arabic and English in the dictionary files (`src/lib/app-i18n-pages.ts` for log-in, the security settings part of `appDict`); no invented claims; no model output.
- **Expand only** (rule 679). New keys and routes only; no stored shape of an existing family changes; rollback to any earlier build is safe; no script.
- **Checks.** Every task ends with `npx next typegen && npm run check` green in the default mode AND with `TEST_PERSONS=legacy npm test` green, and the test count not lower than before the task (record both counts in the commit message). Tasks that touch a route or a page also run `npx next build` before their commit. Commit per task; push nothing until the plan is done; then one push and a draft PR (`gh pr list --head <branch>` first, `gh pr create --draft`), CLAUDE.md CI rules (rule 772).
- **Docs in the same commit** as the behaviour they describe; `docs/system/tests/2400-passkeys.md` is updated by every task for the rules it pins.

## Review Focus

Reviewers spend their time here; the rest is plumbing.

1. The sign-in verify route: is any path from "credential id in the request" to "session" possible without the forward check (`pkcred` → `getPerson` → `getLogin(person.email).pid === pid` → id in the set → birth → UV → counter) and without `finishLogin`? (rules 2405, 2419, 2423)
2. Re-authentication: can a stolen session add or remove a passkey without the password or code, or after 5 minutes, or from another session? (rules 2407, 2410, 2411)
3. Wipes and moves: after deletion or an address move, does any `passkeys:`, `pkcred:` or `pkreg:` key still name the old pid, and can a new person at the same address inherit anything? (rules 2402, 2424, 2425)
4. The seam: does anything outside `src/lib/webauthn.ts` touch the library, and does the real-crypto test really sign with a generated key? (rules 2409, 2427)
5. Lock order and Redis round trips in `src/lib/passkeys.ts` (rule 2414, no `await db.*` in a loop).
